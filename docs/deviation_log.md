# Deviation log

Every place where the database differs from, or adds to, the ER diagram and the relational
schema in our mid-semester report. The 42 relations, their keys and their foreign keys are
otherwise exactly as in Section 4.2 of the report.

| # | Area | Report | Database | Why | Effect on the design |
| --- | --- | --- | --- | --- | --- |
| D1 | Error reporting | Not covered | One support table `error_log`, a composite type `fn_result`, and helpers `raise_rule`, `fn_ok`, `fn_fail` (`db/05_support.sql`) | The final submission asks for functions that report errors. Every function returns `(ok, code, message, data)`, and every failure is written to `error_log` | None. They are not part of the ER design and no design relation refers to them |
| D2 | Rule 18 | Overlap check by trigger (Section 4.5) | `EXCLUDE USING gist (team_id WITH =, daterange(valid_from, valid_to, '[)') WITH &&)` | PostgreSQL can state "no two periods of one team overlap" as a constraint. It covers every insert and update path, and holds when two sessions write at once, which a trigger only does with extra locking | Stronger enforcement of the same rule. Rule 18 moves from "trigger" to "fully guaranteed" |
| D3 | Rule 24 (bands) | Overlap check by trigger | `EXCLUDE USING gist (tournament_id WITH =, int4range(placement_from, placement_to, '[]') WITH &&)` | Same reason as D2 | Rule 24 moves from "partly" to "fully guaranteed" |
| D4 | Rule 14 (same team) | Overlap check by trigger; the report noted an EXCLUDE constraint as the PostgreSQL option | `EXCLUDE USING gist (person_id WITH =, team_id WITH =, daterange(start_date, end_date, '[)') WITH &&)` | Same reason as D2. The cross-team part (two-way players) still needs a trigger, because it depends on `roster_role` | Rule 14 moves from "trigger" to "partly guaranteed" |
| D5 | Period ends | `valid_to` and `Roster.end_date`; inclusive or exclusive not stated | Both are **exclusive**: the first day the row no longer applies | A rebrand or transfer on day *d* closes the old row with *d* and opens the new one with *d*, so there is no gap and no overlap. This is what makes the half-open `'[)'` ranges in D2 and D4 correct | A stint covers a date *x* when `start_date ≤ x < end_date` (or `end_date` is empty). Season, stage, tournament, phase and penalty dates stay inclusive calendar days |
| D6 | `Player.activision_id` | `UNIQUE` | `NOT NULL UNIQUE` | Every CDL and Challengers player competes on an Activision account, so the id always exists and identifies the player. `faceit_id` stays optional because only Challengers uses FACEIT | `activision_id` becomes a true candidate key of `player` (a column that may be empty cannot be one) |
| D7 | Surrogate keys | «id» attributes | `integer GENERATED BY DEFAULT AS IDENTITY` | `BY DEFAULT` lets the seed files carry fixed ids, so tests and the demo can refer to "map 3" or "team 1". After each seed stage the loader moves every counter past the highest id loaded | None |
| D8 | Names | CamelCase relation names (`PlayerGameStats`) | snake_case (`player_game_stats`) | PostgreSQL folds unquoted names to lower case; snake_case avoids quoting every name | None. Section 4.2's names map one to one |
| D9 | Phase 3 support objects | Not covered | `raise_total` (codes `T0001` to `T0004` for the four total-participation constraints); helper functions `match_date`, `has_stint`, `check_listed_player` and the `*_label` functions that put names into error messages | The participation constraints have no rule number, so they get their own code family. The helpers keep each check function short | None. No table or column added |
| D10 | Rule 3 | Links stay in one tournament; each slot fed once | Also: a match cannot feed itself | A self-link would make a match wait for its own result | Stricter. No valid bracket is refused |

## Readings of rules the report left open

These are not changes to the design; they fix one meaning where the report's wording allows
more than one, so the triggers and the functions agree.

| # | Rule | The question | Our reading | Why |
| --- | --- | --- | --- | --- |
| D11 | 12, 16 | What is "the match date"? `match.scheduled_at` is a timestamp | The UTC date of `scheduled_at`; while a match has no time, its tournament's `start_date`. A match with neither cannot have players listed | Every session gets the same date whatever its time zone. Stints change on whole days, so a date is what the rules compare |
| D12 | 16 | A league has `min_age`, but the player's `date_of_birth` is empty | The player cannot be listed in that league's matches | "Must be at least min_age" cannot be shown without a birth date |
| D13 | 21 | Can a match-forfeit penalty point to one of the match's games? | No: it points to the match, with `game_number` empty. A game-forfeit penalty points to a game | Keeps the two penalty types distinct, matching the two forfeit levels |
| D14 | 4 | "Stops once a team has won more than half": must later game rows be absent? | No game after the deciding game may have a result. A scheduled game row may exist and stays unplayed | Lets the veto step create all game slots up front without breaking the rule |
| D15 | 17 | If a player changes region later, are their past matches re-checked? | No. The region is checked when the player is listed for a match | A move later does not make a past match invalid. Changing the tournament's region does re-check its listed players |

## How to add an entry

Add a row whenever the SQL stops matching the report: a column type that changes meaning, a
key or foreign key that changes, a rule enforced differently from Section 4.5, or a table or
column added. Give the reason and say whether it changes the design. This file is the source
for the "deviations" slide of the final presentation.
